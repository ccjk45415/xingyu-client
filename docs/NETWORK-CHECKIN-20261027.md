# 云端签到、成功提醒与网络代理测试

## 已上线的云端修复

旧代码每天北京时间 10:00 执行；8:40 前不会开始每日任务。反馈账号的授权有效，旧日志在 10:00 确认过今日已签到，但旧日志没有记录是否实际执行了签到 POST，不能据此把用户手动签到归为云端成功。

新的每日目标时间为北京时间 08:01，即官网 08:00 重置后一分钟。网络失败按 1、5、15、30、60、120 分钟逐步退避，每个签到周期最多 12 次，受全局额度限制。401 需要重新授权；临时 403、419、跳转、超时不直接清空授权。已有任务只迁移一次，原定时间保留为诊断字段。开启云端的独立同意和七天授权期限不变。

兼容旧客户端的历史状态仍使用 `signed`，新增 `performed` 表示是否实际执行；仅确认已有签到不会生成新的云端成功提醒。用户诊断记录只保存在本机私有工具目录，公开证据不包含反馈用户的 UID、凭据或历史。

## 客户端功能

- 设置 → 通知 → 签到成功：显示 Android、Windows、macOS 或云端服务，以及手动、打开应用、后台、云端四种方式。只有成功的签到 POST 和随后确认的签到状态才能产生本端执行记录；已签到、失败、来源不明的旧记录不会冒充本端成功。
- 同一天按官网 08:00 重置周期去重。同一账号在任一端确认后，其余端下次同步清除未读。云端授权可以独立同步自己的签到消息，不强制开通聊天室；消息仅包含时间、客户端、方式等元数据，不携带网站 Cookie。
- 安卓原生后台成功后保存记录、尝试同步，并按用户通知开关提醒。云端通知沿用系统定期检查，可能延迟；没有新增实时推送服务。后台任务仍受 Android 省电、网络和强行停止限制。
- 登录页和设置页均有“网络与代理”：跟随系统、直接连接、手动 HTTP 代理；支持全部连接或仅安装包更新与热补丁。Clash 使用 HTTP/Mixed 端口。电脑本机可填 127.0.0.1；手机填运行 Clash 的电脑局域网 IP，并在 Clash 开启允许局域网。
- 补丁引擎通过进程内代理环境使用同一配置，不修改系统代理、注册表或证书校验。原生补丁检查运行期间延后应用环境变量变更，避免中途改动请求配置。安卓新安装包同时覆盖系统后台任务的代理；旧基础包只能热更新应用内连接与补丁代理，界面会说明后台限制。

## 发布交付

Android 0.13.5 (41)、Windows 0.7.4 (31)、macOS 0.3.4 (9) 经构建与校验后，按用户最新指令提升为正式更新安装包。沿用这些已验证基础包的更新通道 `qa-20261027`，此名称不影响正常静默更新；后续补丁脚本已绑定对应的版本、构建参数和通道。此次以完整安装包交付，安卓原生后台代理及通知需要安装新版。

1. 在网络设置保存地址和端口，测试网站、星屿服务及补丁域名，再使用“检查补丁”。手机测试局域网代理时需与电脑网络互通。
2. 重启后核对代理配置是否保留；选择“仅更新与热补丁”时，网站仍按系统连接方式访问。
3. 在通知设置启用签到成功；应用外提醒还需要原有系统通知权限。当天已签到不会重复签到或补造来源记录，需要在下一次实际成功后检查来源和跨端已读。

验证：66 项服务端测试；255 项 Flutter 测试（3 项条件跳过）；10 组隔离的安卓原生服务测试及 API 36 编译；原始 Windows Shorebird 引擎在初始化后确实向指定 HTTP 代理发出补丁检查 CONNECT。代理测试使用本机返回 502 的隔离代理停止真实补丁请求，没有关闭 TLS 校验或读取用户的补丁缓存。安卓测试不等于三星 Android 16 真机后台验收。
